## 0. Headline

**The lifetime layer is repaired. The displaced-vertex branch of the recast now runs end to end**:
`Trackless Acc = 19.2%` (A) and `43.2%` (B), against `0.0%` before.

Two things must be said plainly, because both contradict the mission brief:

1. **The primary hypothesis is disproven.** The SLHA `isResonance` flag was never the cause.
   The real cause is `LesHouches:setLifetime`, whose default (`1`) means "sample a lifetime for
   τ leptons only, take everyone else's decay time from the LHE `VTIMUP` field" — and the toy
   generator writes `VTIMUP = 0`. `ResonanceDecays` displaces daughters perfectly well when
   `tau > 0`; it was simply never given a `tau`.

2. **The prescribed staged repair does not work for this benchmark, and the rejected-by-omission
   one-liner does.** The staged path produces displaced vertices but yields **zero** DV acceptance,
   because hadron-level decays cannot decay W/Z bosons. The working repair is a single card line
   and needs **no code change at all**.

| Repair | Criteria 1–7 (mechanism) | Criteria 8–9 (DV physics) | Verdict |
|---|---|---|---|
| `baseline` (no repair) | fails 1,3,5,6,7 | fails 8,9 | reproduces the Mission 01 failure |
| **`setlifetime`** | fails **only** criterion 1 | **passes 8 and 9** | **works — recommended** |
| `staged` (prescribed) | passes 1–7 | **fails 8 and 9** | mechanically correct, physically dead |

Neither path passes all nine criteria. Criterion 1 (`isResonance == false`) is a restatement of the

sees anything, and only `setlifetime` passes them.

## 1. Root cause, with source evidence

`ProcessContainer.cc:843-846` (PYTHIA 8.308), the LHE → process-record path:

```cpp
// Check if need to store lifetime.
double tau = lhaUpPtr->tau(iOld);
if ( (setLifetime == 1 && idAbs == 15) || setLifetime == 2)
   tau = process[iNow].tau0() * rndmPtr->exp();
if (tau > 0.) process[iNow].tau(tau);
```

with `setLifetime = mode("LesHouches:setLifetime")` (`ProcessContainer.cc:218`), documented in
`xmldoc/LHEF.xml:113` as **`default="1"`**:

- `0` — all decay times taken from the Les Houches input.
- `1` — **default**: τ leptons sampled by PYTHIA; *all other decay times taken from the LHE input*.
- `2` — all decay times generated by PYTHIA, disregarding the LHE values.

`scripts/generate_toy_lhe.py` writes the `VTIMUP` column as `0.0000000000e+00`. So at default
settings `tau = lhaUpPtr->tau(iOld) = 0`, the `if` does not fire because `idAbs != 15`, and the
LLP enters the event with `tau = 0`.

Both decay machineries then behave correctly *given* `tau = 0`:

- `ResonanceDecays.cc:125-128` — `if (process[iDec].hasVertex() || process[iDec].tau() > 0.)`
  then daughters get `vProd = vDec`. With `tau = 0` this is skipped, so daughters sit at the origin.
- `ParticleDecays.cc:344-348` — same guard, and note it sets `tau` for **daughters only**, never
  for the decaying particle. Nothing downstream ever back-fills the LLP's own `tau`.

**`isResonance` is a red herring.** `ResonanceDecays.cc:55-56` does gate on `decayer.isResonance()`,
which is why clearing the flag changes *which machinery* decays the LLP — but not *whether it is
displaced*. Displacement depends only on `tau > 0`.

## 2. Why the five Mission 01 attempts failed

| # | Attempt | Why it failed |
|---|---|---|
| 1 | `9900035:isResonance = false` in the `.cmnd` | The particle is created by the SLHA reader *inside* `init()`. At `readFile()` time PDG 9900035 does not exist, so the line cannot bind — it segfaulted. Ordering problem, and it targeted the wrong flag anyway. |
| 2 | `setIsResonance(false)` in code after `init()` | Correctly moved the LLP out of `ResonanceDecays` (`ResonanceDecays.cc:56`), so it fell through to hadron level. But `ParticleDecays` also guards on `tau() > 0` (`ParticleDecays.cc:344`), and `tau` was still 0. Wrong flag: it changed the decayer, not the lifetime. |
| 3 | Native `9900035:new` + `isResonance = false`, bypassing SLHA | Same as #2. `tau0` was set correctly, but `tau` is not `tau0`: nothing sampled one, because `LesHouches:setLifetime` still defaulted to 1. |
| 4 | `ProcessLevel:resonanceDecays = off` | Suppressed process-level decays, but the LLP was still `isResonance = true`, and hadron level declines to decay resonances. The LLP survived to status 62 and never decayed at all. |
| 5 | #4 + `setIsResonance(false)` after `init()` | The LLP now decayed at hadron level, but still with `tau = 0` — for the third time the missing ingredient was the *lifetime*, not the *decayer*. |

Every attempt manipulated **who decays the LLP**. None of them addressed **whether a proper
lifetime was ever sampled**. That is why all five produced `rDec = 0`.

### The repair needs no code change

`LesHouches:setLifetime = 2` is an ordinary setting, so it binds at `readFile()` time. Adding that
single line to the `.cmnd` card and running the **unmodified baseline code path** gives results
identical to the patched `setlifetime` path, to the last digit:

```

patched  setlifetime path : R_vertex>4mm 19.2%  SelDecayProd 19.2%  InvMass 19.2%  Acc 19.2%  AccxEff 14.33666%
```

The shipped cards were deliberately left unmodified so `baseline` keeps reproducing the documented
Mission 01 failure. **Recommendation: adopt the one-line card fix and retire the staged path.**
Per `AGENTS.md` ("prefer minimal, reversible changes"), a card line beats a C++ patch.

## 6. Why the staged path fails — the substantive finding

The staged path displaces the LLP correctly (578/1000 with `Rxy > 4 mm`, daughters displaced
1000/1000) and still yields **zero** DV acceptance. Direct instrumentation of the daughter tracks:

```
staged      : LLP charged final daughters = 2   -> id=24, -24, tau0=0.000, tau=0.000, isFinal
              selected (transvDist>520mm, pT>1) = 0
setlifetime : LLP charged final daughters = 213 -> id=211, -321, ... tau0=7804.5, tau=2221.8
              selected (transvDist>520mm, pT>1) = 161
```

**The W bosons are never decayed.** Staging moves the LLP decay to the hadron level, where
`ParticleDecays` handles ordinary unstable particles — but W/Z are *resonances*, decayed only by
the process-level `ResonanceDecays`. Once `S → W⁺W⁻` happens at hadron level, the W bosons are
final-state and stable, so the event contains 2 charged "tracks" (the Ws themselves) instead of
~200 hadrons. The recast's track requirement (`≥5` selected decay products with
`βγ·τ > 520 mm`) can never be met.

For this benchmark `BR(WW) + BR(ZZ) = 0.70`, so the staged path destroys 70% of the decay table.
The `bb` (0.25) and `gg` (0.05) fractions would hadronize normally, but the resulting vertices
still fail the ≥5-track cut often enough to leave acceptance at zero.

There is a second, independent symptom: staged `Trackless Jet Selection` is **40.8%** versus
21.8% for `setlifetime`. The undecayed W bosons are clustered as high-pT jets, *inflating* the
jet selection. A staged run therefore does not merely lose acceptance — it reports a corrupted,
optimistic jet cutflow. This is exactly the kind of number that would look plausible in a table
and be wrong.

**This generalizes beyond the toy.** Any LLP with decays to W/Z/t — including the paper's scalar
and any 2HDM heavy scalar — is incompatible with hadron-level staging. The mission's fallback
(a toy parent resonance `gg → X → LLP LLP`) was **not** implemented: it is unnecessary, since
`setlifetime` works, and it would not address this defect anyway.

- **Input hashes identical.** Both cards read the same LHE,

- **Modified selection remains looser or equal:** `Trackless Jet Selection` B = 50.6% ≥ A = 21.8%.

## 9. Remaining limitations

- **`TOY_LIFETIME_PLUMBING_TEST`.** The LHE is synthetic two-body `gg → SS` with fixed
  `√ŝ = 1 TeV` and deterministic kinematics. It is not MadGraph and does not represent off-shell
  Higgs production. The βγ distribution is an artifact of the toy, so `L3D` and `Rxy` are
  plumbing observables, not predictions.
- **`AB_RECAST_INFRASTRUCTURE_TEST`.** The 19.2% / 43.2% acceptances demonstrate that the DV
  branch is wired correctly. They are **not** efficiencies and must not be compared with the
  paper's Table II (2.9% / 11% for the S250 point), which is anchored to real event generation.
- The BRs in the toy SLHA (`bb`/`WW`/`ZZ`/`gg` = 0.25/0.50/0.20/0.05) are an executable example,
  not the paper's values and not a 2HDM point.
- The vertex- and event-efficiency parameterizations are now exercised, but validated only in the
  sense that they run and return finite values on toy input.
- `LesHouches:setLifetime = 2` disregards LHE `VTIMUP` **globally**. That is correct here (PYTHIA
  has `tau0` from SLHA, and the LHE carries no lifetimes), and matches PYTHIA's own caveat for
  option 2. But a future MadGraph LHE that *does* set `VTIMUP` would have those values silently
  overridden. Revisit this when real LHE input arrives.
- Statistics are 500 events. The high-statistics cross-check used 5000 toy events; the paper used
  10⁶ per benchmark.
- The `staged` code path is retained for comparison only. **It must not be used for physics**: it
  leaves W/Z undecayed, zeroes DV acceptance, and inflates the jet cutflow.
